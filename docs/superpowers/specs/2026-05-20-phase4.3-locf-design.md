## Overview

### Goal

p30 cells（30-day rolling avg funding rate）在 Bitfinex 上是稀疏 channel — 4.3 shadow window 24h+ live data 觀察 fUSD_p30 latest candle 6h ago、fUST_p30 latest 2h ago，其他 p2/a30 cells 每 hh:00 都有 candle。本 spec 設計 production 端 LOCF (Last Observation Carried Forward) + staleness budget 機制讓 p30 strategies 不被跳過，同時並行 sparse-ify Phase 3b WFO 重跑 validate backtest fidelity，且設 G2 live calibration audit 為 4.4 canary ship gate。

### Non-goal

- 不碰 strategy code（RP / MR `observe()` / `decide()` 保持 staleness-blind）
- 不碰 decision module fallback policy（4.3 shadow phase 沒 trade execution，stale-signal-aware position cut 推遲 4.4）
- 不對 p2 / a30 cells (99% dense backfill) 跑 LOCF backtest WFO 重跑（identity transform 數學成立 + unit test 證明，跑 WFO 是 wasted compute）
- 不設 multi-imputation 對比 (mean-fill / KNN / spline) — Lopez de Prado white paper standard，single-eng startup 不採
- 不建 Grafana / Axiom dashboard — sync Phase 3b research note pattern，4.4+ 才考慮 dashboard
- 不解 Bitfinex p30 channel 上游 sparseness 是否 API bug（黑箱問題，假設 sparseness 是 long-run reality）

### Scope packaging decision

| 派別 | 做法 | 為何不選 |
|---|---|---|
| Runtime-only spec | 只 LOCF runtime + observability，backtest re-run defer | 違反 wiki 已寫「避免 daemon/replay engine 行為差導致 backtest/live divergence」原則 |
| Mega-spec | LOCF + decision policy + G2 + 4.4 canary entry 全包 | Scope 太大；decision policy 應 evidence-based wait G2 audit 結果 |
| **3-axis spec** (本 spec) | LOCF runtime + sparse-ified backtest re-run + G2 live calibration audit 並行 | wiki 4.3 backlog recommend 三層；ship gate 兩 axis AND (backtest + G2) 對應 Phase 4 conservative discipline |

業界對「production semantic 改動 + backtest semantic 並行驗」mainstream = Two Sigma scoped re-run + variance audit (Approach 2 in brainstorm)。對 single-eng startup pre-canary 階段，跑 affected cells + sensitivity sweep grid (6h/12h/24h) 比 Renaissance full-universe re-run cost 效率高 10×，比 production-first (Bloomberg style) ship-gate 硬。

## Architecture

### Shared primitive: `reindex_and_ffill` in `candles/service.py`

三層 (daemon live / replay engine in-process / Phase 3b backtest WFO) 都 call same function，保證 byte-equivalence (Phase 4.1 CP1 property test 模式 extend)。

```
                       ┌─ candles/service.py ───────────┐
                       │  reindex_and_ffill(            │
                       │    candles, ref_mts,           │
                       │    freq_ms=3_600_000,          │
                       │    max_gap_hours: int          │
                       │  ) → list[FilledCandle]        │
                       │                                │
                       │  Each FilledCandle:            │
                       │    candle: FundingCandle|None  │
                       │    is_stale: bool              │
                       │    stale_seconds: int          │
                       └──────────────┬─────────────────┘
                                      │
                ┌─────────────────────┼─────────────────────┐
                ▼                     ▼                     ▼
         daemon                 replay engine          backtest WFO
         (1 call/tick)          (1 call/tick)          (1 call/window)
                │                     │                     │
                └─────────────────────┴─────────────────────┘
                                      │
                          Property test (100 iter)
                          → byte-equivalent across layers
```

業界對照: **Approach C (Citadel-style shared primitive + thin layer-specific wrappers) + Pattern 1 (single batch API, no point-in-time primitive)**。daemon hourly tick 不是 sub-second latency-sensitive，batch reindex 168h × 11 cells = 1848 rows ms 級 cost，多餘 API surface 不划算。

### Function contract

```python
# modules/candles/service.py

from dataclasses import dataclass
from .schemas import FundingCandle

@dataclass(frozen=True)
class FilledCandle:
    candle: FundingCandle | None  # None == beyond budget (hard tier)
    is_stale: bool                # True == ffilled from earlier source
    stale_seconds: int            # 0 if fresh; (ref_mts - source.mts)/1000 if stale

def reindex_and_ffill(
    candles: list[FundingCandle],
    ref_mts: int,
    freq_ms: int = 3_600_000,
    max_gap_hours: int = 2,
) -> list[FilledCandle]:
    """Reindex sparse candle list to a full hourly grid ending at ref_mts,
    forward-filling missing slots up to max_gap_hours of staleness.
    Beyond max_gap_hours, slots remain (candle=None, is_stale=True, stale_seconds=...).

    Invariants:
    - len(output) == n hourly slots from candles[0].mts (or earliest covered) to ref_mts
    - output[-1].candle.mts (if not None) is within freq_ms tolerance of ref_mts
    - For 100% dense input on freq_ms grid: output candles match input 1-to-1 + all (is_stale=False, stale_seconds=0)
    - Deterministic: same input → same output across N invocations
    """
```

### Layer-specific wrappers

**Daemon (`modules/marketfeed/scheduler.py::on_scheduler_tick`)**:

```python
candles_window = fetch_lookback_window(cell, ref_mts, lookback_hours=168)
filled = reindex_and_ffill(
    candles=candles_window,
    ref_mts=ref_mts,
    max_gap_hours=cell_config.staleness_budget_hours,
)
latest = filled[-1]

if latest.candle is None:
    # Hard tier — beyond budget
    if probe.current_status(HealthTarget.SIGNAL_PIPELINE, cell.key) != Status.DEGRADED:
        probe.update(
            target=HealthTarget.SIGNAL_PIPELINE,
            cell_key=cell.key,
            status=Status.DEGRADED,
            reason="stale_exceeded",
            stale_seconds=latest.stale_seconds,
            budget_seconds=cell_config.staleness_budget_hours * 3600,
        )
    return  # skip signal emit for this cell × tick

# Soft tier OR fresh — emit signal with staleness metadata
signal = strategy.compute(filled, ...)
emit_signal_event(
    signal=signal,
    is_stale=latest.is_stale,
    stale_seconds=latest.stale_seconds,
    budget_seconds=cell_config.staleness_budget_hours * 3600,
)
if probe.current_status(HealthTarget.SIGNAL_PIPELINE, cell.key) != Status.HEALTHY:
    probe.update(..., status=Status.HEALTHY)  # transition restore
```

**Replay engine**: 同 daemon (in-process dual-compute byte-equivalence, Phase 4.1 CP1 invariant)。

**Backtest (`scripts/run_phase4.3_locf_wfo_matrix.py`)**:

```python
for cell_key in ["fUSD_p30", "fUST_p30"]:
    for strategy_cls in [RatePercentile, MeanReversion]:
        for budget_hours in [6, 12, 24]:
            for wfo_window in walk_forward_windows(...):
                raw_candles = repository.get_candles_in_range(cell_key, wfo_window)
                filled = reindex_and_ffill(
                    candles=raw_candles,
                    ref_mts=wfo_window.end_mts,
                    max_gap_hours=budget_hours,
                )
                # Unwrap: ffilled rows 保留 (candle != None, close = last-known via LOCF);
                # hard-tier None rows skip (mirror daemon hard tier behavior)
                unwrapped = [f.candle for f in filled if f.candle is not None]
                result = run_backtest(unwrapped, strategy_cls, ...)
```

**Strategy code 不改 — call site mechanics**:

- `FundingCandle` Pydantic class 不變；ffilled row 仍是 FundingCandle instance，只是 `close` 帶 last-known LOCF value
- 三層 wrapper 解開 `FilledCandle.candle` 後給 strategy `observe(candle)` — strategies 仍接 FundingCandle iterable，既有 `if candle.close is None: skip` guard (per Phase 4.1) handle hard-tier None
- Strategy 看 ffilled rows 上的 repeated close → rolling window stats (variance / EMA / percentile) 自然 compress；這正是 sensitivity sweep 要 measure 的 magnitude
- `is_stale` / `stale_seconds` 是 envelope-level metadata，由 daemon scheduler attach 到 SignalEventPayload，strategies 不 aware

業界對 tagged event payload: **flat optional fields + reason tag** (vs nested metadata dict)。對 APL dotted field bracket-quote 踩坑 (Bug A 5/20) 是 lessons learned 直接 response — flat field 在 APL query 不需 bracket workaround。

```python
class HealthCheckPayload(BaseModel):
    target: HealthTarget         # SIGNAL_PIPELINE, BITFINEX_WS, DB, ...
    status: Status               # HEALTHY, DEGRADED, DOWN
    cell_key: str | None = None  # per-cell context (SIGNAL_PIPELINE only)

    stale_seconds: int | None = None      # NEW — reason="stale_exceeded"
    budget_seconds: int | None = None     # NEW — reason="stale_exceeded"
    last_msg_age_ms: int | None = None    # existing — target=BITFINEX_WS
    retry_count: int | None = None        # existing — reason="connection_lost"
```

### Reason-to-escalation-policy matrix (D4 scan_staleness carve-out)

| reason | scan_staleness 升 3× threshold → Fatal | 適用 HealthTarget |
|---|---|---|
| `connection_lost` | ✓ | BITFINEX_WS, BITFINEX_REST |
| `db_unavailable` | ✓ | DB, db_keepalive |
| `task_hung` | ✓ | candle_writer, axiom |
| `stale_exceeded` | ✗ — 永遠停在 DEGRADED | SIGNAL_PIPELINE |

`stale_exceeded` 為何不 escalate fatal: sparse 是 expected behavior (Bitfinex p30 channel 物理特性)，不是 system failure。未來 4.4 若觀察「stale_exceeded > X consecutive hours」需要 paging escalation，可加 consecutive-hours cap，4.3 不預設加。

## Backtest Validation Strategy

### Approach 2 — Scoped p30 re-run + budget sensitivity sweep (Two Sigma mainstream)

業界對「production semantic 改動 backtest validation」spectrum:

| Approach | 代表 | 適用 |
|---|---|---|
| Renaissance full-pipeline (Approach 1) | RenTech / DE Shaw | multi-eng firm；overkill for single quant |

### Identity transform proof for p2/a30 (Lopez de Prado mathematical claim + unit test)

p2/a30 backfill 99% dense (fUSD/fUST p2/a30 candles 候 38153-38164 vs 38544 max post-2022-01-01 window)。`reindex_and_ffill` 在 100% dense input on `freq=1h`:

- Reindex to full hourly range → input 本已 full → no-op
- Ffill on no-gap → no-op
- Output candle 等於 input candle 1-to-1 + `(is_stale=False, stale_seconds=0)` wrap

**Unit test 替代 WFO 重跑**，省 16 wasted runs (24 - 12 = 16)：

```python
# tests/test_candles_service.py
def test_locf_identity_on_dense_input():
    candles = generate_dense_hourly_candles(start_mts=..., n=168)
    filled = reindex_and_ffill(candles, ref_mts=candles[-1].mts, max_gap_hours=12)
    assert len(filled) == 168
    for original, wrapped in zip(candles, filled):
        assert wrapped.candle == original
        assert wrapped.is_stale is False
        assert wrapped.stale_seconds == 0
```

### Backtest ship gate — GREEN/YELLOW/RED (extend Phase 3b binary gate × budget tier)

For each `(cell, strategy)` pair:

- **GREEN** = 12h variant qualified (≥ 60% win-rate + ≥ 5% margin) → ship 為 4.4 canary candidate；cells.yaml 保持 12h
- **YELLOW** = 12h fail but 24h qualified → cells.yaml 該 cell pair `staleness_budget_hours` 拉到 24h；ship 為 4.4 candidate
- **RED** = 24h fail → disqualify cell pair from 4.4 canary (LOCF semantic break strategy on cell)

**Hypothesized RED for fUST_p30 MR**: Phase 3b selective observation semantic 已 NOT qualified (51.28% win-rate < 60% floor)。LOCF 預期不會把 win-rate distribution 拉到 60%+（ffilled rows narrow variance，通常不會 lift mean win-rate)。但 ship gate 仍 **data-driven** — sensitivity sweep 跑出來若 fUST_p30 MR 任一 budget variant qualified，按正常 GREEN/YELLOW/RED matrix 處理；若 hypothesis confirmed (全 budget RED)，不算 LOCF break 而是 carry-over from Phase 3b。

## G2 Calibration Audit Plan

### Window length & sample size

- **Window**: 2-4 weeks shadow live data (sync wiki "W3-W4 shadow run + G2 calibration" plan; Two Sigma mid-range standard)
- **Min sample size**: 30 stale signals per `(cell, strategy)` pair (Lopez de Prado n=30 binomial test min power for 60% vs baseline)
- **Expected reach**: p30 sparseness 50-66% × 24 hh:00 ticks/day × 14 days = 168-225 stale signals per cell × 2 strategies → 輕鬆 ≥ 30

### Stale subset filter — binary `is_stale=True`

Tier-based (0-2h / 2-6h / 6-12h short/long-stale) 推遲到 4.4 if evidence base 需要。4.3 first-ship 保持 binary。

### Comparison baseline — Phase 3b qualification threshold 直接套用

Stale subset 沿用 ≥ 60% win-rate + ≥ 5% margin gate（sync user-selected G2 gate criterion A: 沿用 Phase 3b qualification logic）。不另設 within-window fresh-subset baseline（regime drift 風險 + 14d sample 不足）。

### Audit script — `scripts/g2_audit_locf.py`

1. F3 query → sparseness rate per cell per day, validate window covered enough stale events
2. F1 query → all is_stale=True signals in window
3. F2 query → all is_stale=False signals for cross-reference
4. Join with decision events → compute win/loss per stale signal (decision module 已 emit `pnl_proxy` per Phase 4.1 schema)
5. Compute per `(cell_key, strategy)` stale-subset stats: eligible / wins / win % / margin / health %
6. Emit GREEN/YELLOW/RED verdict per row (gate criterion same as Backtest gate)

Output: `docs/research/2026-05-2x-phase4.3-locf-g2-audit-log.md` (sync Phase 3b results doc schema)

### Edge cases

| Case | Handling |
|---|---|
| Stale sample size < 30 | YELLOW + recommend extend window 1-2 weeks |
| No 24h+ gap event in window | 24h budget variant "untested in live"；fall back to trust Section Backtest sensitivity sweep result。Spec 明示 |
