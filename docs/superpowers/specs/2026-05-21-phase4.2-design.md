# Phase 4.2 — Real-Money Safety + Execution + DI Executor Abstraction Design

**Spec lock date**: 2026-05-21
**Parent**: `2026-05-18-phase4-roadmap-design.md`
**Sibling (sequel)**: 4.3 Stability validation + G2 calibration（既有 in-progress；本 spec 產出 L2 guard code，threshold 由 4.3 calibrate）
**Sibling (sequel)**: 4.4 First canary deployment（本 spec 留 `BitfinexLiveExecutor` + fill_tracker enable 翻 flag）

## Overview

### Goal

替 daemon 增加一條完整 execution pipeline（strategy signal → safety guard chain → executor → fill tracker），所有 component 經 DI 抽象，4.2 ship 只 wire `EchoPaperExecutor`，`BitfinexLiveExecutor` 不接進 daemon，留 4.4 canary 一起 wire。

### Why now

- Phase 4.2.1 shadow stable，4.3 LOCF spec 已 ship 進 prod，daemon stabilization debt 清完
- Phase 4.4 canary 前必須 ship safety harness + executor abstraction，否則 real-money signal pipeline 無防護
- 4.2.0 是 daemon stabilization sub-phase，跟本 spec 是不同議題（本 spec 才是 4.2 main brainstorm 結果）

### Out of scope（明確 carve-out）

| Item | Why deferred | Where |
|---|---|---|
| Real Bitfinex auth ws / REST live order placement | 4.2 走 ports & adapters，real adapter 跟 first canary 同 phase 接 | 4.4 |
| L2 calibrated guards 的 threshold value | 需 W3-W4 shadow data 校準 | 4.3 G2 calibration |
| SaaS auth / vault / KMS / billing / KYC | API key 託管在多數司法管轄區是 regulated activity | Phase 5+ separate spec |
| Multi-tenant runtime / per-tenant resource isolation | 4.2 加 AccountContext seam（hardcoded `default`），完整 SaaS 另開 spec | Phase 5+ |
| Partial fill / latency / slippage models | 4.4 real data 來才校 | 4.5+ if divergence |
| ws push fill tracker upgrade | funding lending fill 是小時/天級，REST polling 已夠 | Phase 5 upgrade |
| Mutation testing | over-engineering for 4.2 scope | optional later |

## Core Design Decisions

7 個核心 decision，brainstorm 過程逐一 surface industry best practice 後選定：

| # | Decision | Choice | Rationale |
|---|---|---|---|
| 1 | Scope boundary | abstraction + paper executor + safety harness only；BitfinexLiveExecutor learning spike (`scripts/bfx_offer_spike.py`) **不接進 daemon** | Solo + real-money + concept stage → 物理隔離 > flag 信任。Hexagonal port-adapter pattern 從 4.2 強制抽象，無結構債。Crypto OSS bot 主流 (Hummingbot/Freqtrade) 走 day-1 wired 因為 multi-user OSS 需早收 issue，本場景不適用 |
| 2 | Multi-user direction | SaaS Phase 5+；4.2 加 AccountContext seam（hardcoded `account_id="default"`），schema 從 day-1 有 `account_id` field | Hybrid pattern：20-30 LOC + 1 dataclass 換 Phase 5 不用 rewrite executor/safety/event schema。Process-per-user 受 Bitfinex 30 conn/IP rate limit；shared runtime 從 day-1 over-engineer |
| 3 | Safety architecture | Pre-trade guard chain（decorator/middleware-style）+ per-guard heartbeat | Hummingbot / Bloomberg Tradebook / IB risk gateway 標準 pattern。加 per-account rule 時直接 register 新 GuardRule，不改 chain 結構。比 god SafetyController class 易拆 multi-user |
| 4 | Kill-switch trigger | Layered：L1 hard guards (manual/auth/heartbeat/cap) ship 4.2 always-on；L2 calibrated guards (loss/drawdown/divergence) code 寫完 disabled-by-default，4.3 calibrate threshold，4.4 逐個 enable | SEC Rule 15c3-5 layered control structure + Hummingbot/Freqtrade 演進路徑。「Conservative 占位 threshold」是 known anti-pattern（confabulated value 永遠不被校準） |
| 5 | Fill detection | `RestPollingFillTracker` primary @ 30s interval；ws push Phase 5 upgrade | Funding lending fill latency 是小時/天級，real-time ws 無 ROI。Rate budget：4 req / 30s = 8 req/min（30 req/min 預算內）。Spot trading 主流 ws + REST 對賬不適用 funding context |
| 6 | cid + retry | Deterministic cid = `int(blake2b(correlation_id + utc_date, digest_size=8)) & 0x7FFF_FFFF_FFFF_FFFF`；tenacity 3x exp backoff (1/2/4s)；only `httpx.NetworkError | TimeoutException | 5xx` retried；4xx 不 retry | FIX Tag 11 ClOrdID + Stripe Idempotency-Key + CME iLink standard。Bitfinex cid 是 integer，daily uniqueness window |
| 7 | Paper fidelity | Echo-only：submit 同 tick emit order_submit + order_fill (full size, fill_price=signal_rate) | Hummingbot/Freqtrade/Backtrader 預設。「不要 model 你還沒 ground truth 可校的東西」— 4.4 first canary 第一週 reconciliation 才有 empirical distribution，4.5+ 可選加 LatencyModel / PartialFillModel adapter |

## Architecture

```
strategy_engine (existing, signal_engine.py)
        │
        ▼ build tentative DecisionPayload (POST or strategy-internal SKIP)
        ▼
SafetyGuardChain.evaluate(tentative, account_ctx)
        │  ├─ HardGuard:  ManualKillGuard       (env BFX_KILL_SWITCH)
        │  ├─ HardGuard:  AuthHealthGuard       (probe.current_status check)
        │  ├─ HardGuard:  HeartbeatGuard        (5min watchdog on sub-tasks)
        │  ├─ HardGuard:  AllocationCapGuard    (ledger sum + offer ≤ cap)
        │  ├─ CalibratedGuard: RealizedLossGuard   (enabled=false)
        │  ├─ CalibratedGuard: DrawdownGuard       (enabled=false)
        │  └─ CalibratedGuard: DivergenceRateGuard (enabled=false)
        │
        │  asyncio.wait_for(guard.evaluate, timeout=2s) per guard → fail-closed on timeout
        │  Internal exception → fail-closed + safety_trigger(level=critical)
        │
        ├─ blocked → emit safety_trigger event → build FINAL decision (SKIP+SAFETY_BLOCK)
        │            → emit decision event (ONCE, FINAL) → STOP
        │
        ▼ allowed → emit decision event (ONCE, FINAL — outcome=POST)
ExecutorPort.submit(decision, credentials)   ← AccountContext.credentials
        │
        ▼ wired adapter in 4.2 = EchoPaperExecutor
        │
        ├─ emit order_submit (is_simulated=True)
        └─ emit order_fill   (is_simulated=True)

(parallel sub-task in daemon TaskGroup; gated off by default in 4.2)
RestPollingFillTracker._poll_loop (BFX_FILL_TRACKER_ENABLED=true required, default false)
        │  GET /v2/auth/r/funding/offers + /credits (every 30s)
        │  atomic poll (both succeed or abort tick)
        │  diff vs last_state → emit order_fill / order_status_change
        └─ probe.record_heartbeat("fill_tracker")
```

## Public API

### `protocols.py`

```python
from typing import Protocol
from dataclasses import dataclass
from decimal import Decimal
import asyncio

@dataclass(frozen=True, slots=True)
class Credentials:
    """4.2: 從 env BFX_API_KEY / BFX_API_SECRET 載入。
    Phase 5 SaaS: 從 vault per-account 解密。"""
    api_key: str
    api_secret: str

@dataclass(frozen=True, slots=True)
class AccountContext:
    """4.2 always account_id='default'. Phase 5+ multi-tenant."""
    account_id: str
    credentials: Credentials
    allocation_cap_usdt: Decimal

@dataclass(frozen=True, slots=True)
class GuardResult:
    allowed: bool
    guard_name: str
    reason: str | None       # populated when blocked

@dataclass(frozen=True, slots=True)
class SubmittedOrder:
    cid: int                       # Bitfinex int63 cid
    venue_offer_id: str | None     # paper_<uuid12> for paper, int from venue for real
    status: str                    # "submitted" / "failed" / "filled" (paper synchronous)
    raw_response: dict | None      # debug audit, None for paper

class GuardRule(Protocol):
    name: str
    is_calibrated: bool      # True for L2 (enabled=false default)

    async def evaluate(
        self, decision: "DecisionPayload", ctx: AccountContext,
    ) -> GuardResult: ...

class ExecutorPort(Protocol):
    async def submit(
        self, decision: "DecisionPayload", ctx: AccountContext,
    ) -> SubmittedOrder: ...

class FillTracker(Protocol):
    async def poll_loop(self, stop_event: asyncio.Event) -> None:
        """Emits order_fill / order_status_change via event_publisher.
        Atomic poll: both /offers and /credits succeed or abort tick."""
```

### `paper.py`

```python
class EchoPaperExecutor:
    """Synchronous echo: submit → order_submit + order_fill same tick.
    No latency / partial fill / slippage modeling. 4.4 real data → 4.5+ optional fidelity adapter."""

    async def submit(self, decision, ctx) -> SubmittedOrder:
        submit_date = datetime.utcnow().date()  # capture once, immune to midnight race
        cid = generate_cid(decision.signal_correlation_id, submit_date)
        offer_id = f"paper_{uuid.uuid4().hex[:12]}"

        await emit_order_submit(decision, ctx, cid, offer_id, is_simulated=True)
        await emit_order_fill(
            decision, ctx, offer_id,
            fill_size=decision.offer_amount_usdt,
            fill_price=decision.offer_rate,
            is_simulated=True,
        )
        return SubmittedOrder(cid=cid, venue_offer_id=offer_id, status="filled", raw_response=None)
```

### `ledger.py`

class PaperPositionLedger:
    """Event-sourcing: replay order_fill events from Axiom on startup.
    NOT persisted separately — Axiom is SoT (30 day retention).
    AllocationCap reads ledger.current_exposure()."""

    @classmethod
    async def replay_from_axiom(
        cls, account_id: str, since: datetime, axiom_client: AxiomClient,
    ) -> "PaperPositionLedger":

        Axiom unreachable handling: retry 3x exp backoff (1/2/4s) — if still
        unreachable, raise LedgerReplayError at build_daemon → daemon never
        starts → fast fail (NOT silent empty-ledger fallback, since empty ledger
        means AllocationCap permits over-cap exposure → real safety hole).
        Aligns with SafetyConfig load fail at startup pattern (fast fail >
        silent degradation)."""

    def on_order_fill(self, event: OrderFillPayload) -> None:
        """Listener subscribed by daemon to event bus."""

    def current_exposure(self) -> Decimal:

## Data Flow

5 paths（A happy + 4 deviations）。Path 編號對應 testing Section。

### Path A — Happy path

```
1. Scheduler tick (1h boundary)
2. signal_engine.run_tick(cell)
   ├─ strategy → raw signal
   ├─ emit signal event
   └─ build TENTATIVE DecisionPayload (outcome=POST)
3. safety_chain.evaluate(tentative, account_ctx)
   ├─ all hard guards → allowed (within timeout)
   ├─ all calibrated guards skipped (enabled=false)
   └─ GuardResult(allowed=True)
4. emit decision event (ONCE, FINAL — outcome=POST)
5. executor.submit(final, ctx)   ← EchoPaperExecutor
   ├─ submit_date captured once
   ├─ cid = blake2b(correlation_id + submit_date) & 0x7FFF_FFFF_FFFF_FFFF
   ├─ offer_id = "paper_<uuid12>"
   ├─ emit order_submit (is_simulated=True)
   └─ emit order_fill   (is_simulated=True)
6. ledger.on_order_fill (update exposure)
7. probe.record_heartbeat("safety_chain"), probe.record_heartbeat("executor")
```

### Path B — Safety block

```
1-2. same through tentative (POST) built
3. safety_chain.evaluate(tentative, ctx)
   ├─ AllocationCap → BLOCKED (sum + offer > cap)
   └─ GuardResult(allowed=False, guard_name="allocation_cap", reason="cap=500+offer=200>500")
4. emit safety_trigger event (level=warn, correlation_id=tentative.correlation_id,
                              payload: {guard_name, reason, decision_snapshot})
5. build FINAL decision: outcome=SKIP, skip_reason=SAFETY_BLOCK,
                          skip_reason_detail=GuardResult.reason
6. emit decision event (ONCE, FINAL — SKIP)
7. executor NOT called
```

**Single decision event per cycle, immutable** (event-sourcing best practice — FIX / Stripe / OpenTelemetry pattern).

### Path C — Executor transient error → retry → success (4.4 only)

```
1-5. same as A through executor call
5. executor.submit(decision, ctx)   ← BitfinexLiveExecutor (4.4 path)
   ├─ httpx POST /v2/auth/w/funding/offer/submit
   ├─ NetworkError → tenacity retry (1s)
   ├─ 502 → tenacity retry (2s)
   ├─ 200 OK, offer_id=12345678
   └─ emit order_submit (is_simulated=False, cid, offer_id, attempts=3, retry_total_ms=3127)
```

cid 跨 3 attempts 同值 → Bitfinex 自動去重（FIX standard）。submit_date captured 一次防 midnight race。

### Path D — FillTracker reconciliation (4.2 scaffolded, gated off)

```
Every 30s (BFX_FILL_TRACKER_ENABLED=true required):
1. fill_tracker.poll_loop tick
   ├─ atomic poll:
   │   GET /v2/auth/r/funding/offers   ─┐
   │   GET /v2/auth/r/funding/credits  ─┴─ both succeed OR abort tick
   └─ current_state: dict[cid → status]
2. diff vs last_state:
   ├─ cid new in credits → emit order_fill (not is_simulated)
   ├─ cid missing from offers → emit order_status_change ("cancelled" / "expired")
   └─ cid partial fill → emit order_status_change ("partially_filled")
3. last_state = current_state
4. probe.record_heartbeat("fill_tracker")
```

4.2 scope：code 寫完 + mock httpx integration test + schema contract test，daemon **不啟動** loop。4.4 翻 true。

### Path E — Executor fatal error（auth fail）

```
1-4. same as A through decision event emit (FINAL POST)
5. executor.submit(decision, ctx) → 401 Unauthorized → ExecutorAuthError (NOT retried)
6. signal_engine catches ExecutorAuthError:
   ├─ emit order_submit (status="failed", failure_reason="auth_failed")
   ├─ emit safety_trigger (level=critical, guard_name="executor_fatal", reason="auth_failed")
   ├─ emit health_check (target=executor, status=down, reason="auth_failed")
   └─ re-raise ExecutorAuthError → TaskGroup cancel-all → ExceptionGroup propagates to daemon._run
7. daemon._run catches ExceptionGroup containing ExecutorAuthError:
   ├─ flush axiom buffer (best effort)
   └─ sys.exit(EXIT_CODE_AUTH_FAILED)   # 78, called at outer entry point only
8. Koyeb crash-loop-backoff 處理 — 連續 N 次 78 exit → 停止重啟 + alert (依賴既有 Koyeb behavior)
```

**`sys.exit` 只在 `daemon._run`（top-level entry）呼叫**，business logic (signal_engine) 不做 side-effect exit。對齊既有 4.2.0 D4 ExceptionGroup propagation pattern。Auth fail **NOT auto-restart loop**（Google SRE Book ch. 22 anti-pattern）— distinct exit code 區分 transient infra fail。

## Error Handling Policy

| Failure class | Handling |
|---|---|
| **Guard internal exception** | try/except wrap → log + emit safety_trigger(level=critical, reason="guard_internal_error") → fail-closed |
| **Guard eval timeout** (>2s) | asyncio.wait_for → TimeoutError → fail-closed + safety_trigger(reason="eval_timeout") |
| **Executor transient error** | tenacity 3x exp backoff (1/2/4s)，only `NetworkError | TimeoutException | 5xx`. Exhausted → emit order_submit `status=failed reason=transient_exhausted`，**不 raise**，下個 cycle 自然新 decision |
| **Executor fatal (non-auth)** | 4xx logical errors (insufficient_balance, invalid_symbol) → emit order_submit `status=failed` → 不 raise，下個 cycle |
| **Executor auth fail** | ExecutorAuthError → emit safety_trigger(critical) + health_check(down) → `sys.exit(78)` → Koyeb crash-loop-backoff |
| **Event emit failure** (Axiom down) | 既有 axiom emitter fallback to stdout，**不 block** executor。Inherit existing 4.2.0 D4 behavior |
| **SafetyConfig load fail at startup** | `build_daemon()` raise → daemon never starts → fast fail |
| **PaperPositionLedger replay fail at startup** | Axiom unreachable: retry 3x exp backoff → raise `LedgerReplayError` → daemon never starts → fast fail（NOT silent empty-ledger fallback：empty ledger 會讓 AllocationCap 容許 over-cap exposure → real safety hole）|

## Corner Cases

### CC1 — Safety chain heartbeat staleness when no signals fire

**Risk**: 所有 cell strategy-internal SKIP → safety_chain.evaluate 從未被呼叫 → heartbeat 過 5min → scan_staleness 誤判 degraded

**Solution**: heartbeat 由 daemon scheduler tick 觸發（每次 run_tick 入口），不依賴 evaluate 是否真執行。signal_pipeline / safety_chain / executor heartbeat 三者**都在 run_tick 入口 emit**，代表「sub-task 還活著、剛被叫到」而非「剛工作過」。對齊 NASA Power-of-10 watchdog 原則。

### CC2 — cid generation race across UTC midnight boundary

**Risk**: attempt 1 in date Y (cid_Y)，tenacity exp backoff 7s 跨午夜，attempt 2 date Y+1 (cid_Y+1) → Bitfinex 看成兩個不同 order → duplicate submit

**Solution**: `submit_date = datetime.utcnow().date()` 在 `executor.submit()` 一進來就 capture，所有 retry 用同一個 date。Code: cid 計算在 retry loop 外。對齊 FIX protocol「ClOrdID generated at submit entry, immutable across retries」。

### CC3 — FillTracker partial poll failure

**Risk**: `GET /offers` 200，`GET /credits` NetworkError → 拿不到完整 venue state → diff 誤判 "filled offer 但 credits 沒拿到" 為 "cancelled" → emit false `order_status_change`

**Solution**: **Atomic poll** — 任一失敗整 tick abort，last_state 不更新。連續 N=3 次失敗 → emit `health_check(fill_tracker, status=degraded)`。Never emit order events with partial data。Inspired by RDBMS atomic transaction。

### CC4 — EchoPaperExecutor × FillTracker invariant violation

**Risk**: paper executor emit `paper_<uuid>` offer_id，fill_tracker 打 Bitfinex (真 venue) → 永遠看不到 paper_ cid → emit false `order_status_change="cancelled"` 給所有 paper offers

**Solution**: **invariant at registry** — `build_executor(env)` validates: `BFX_FILL_TRACKER_ENABLED=true` 要求 `BFX_EXECUTOR=bitfinex_live`。Mismatch → `ConfigError` at `build_daemon()` 不起。4.2 default：`BFX_EXECUTOR=paper, BFX_FILL_TRACKER_ENABLED=false`，4.4 兩者一起 flip。Defensive code 加 paper offer_id prefix check：fill_tracker 看到 cid 對應 offer_id startswith `paper_` 時 raise InvariantError → daemon crash → Koyeb restart。

### AllocationCap state source (implicit corner case)

- 4.2 paper：`PaperPositionLedger` event-sourcing replay from Axiom on startup（30 day window），daemon restart 後 ledger 完整重建。**避免 ephemeral memory restart 重置 anti-pattern**（剛 fix 過 4.3 LOCF cold-start divergence，再加一個 ephemeral state = 重蹈覆轍）
- 4.4 real：AllocationCap queries `fill_tracker.current_state` 取真實 venue active offers + credits sum
- Cap-then-fill race 在 echo-only 不存在（synchronous）；4.4 latency model 加進來時要重審
