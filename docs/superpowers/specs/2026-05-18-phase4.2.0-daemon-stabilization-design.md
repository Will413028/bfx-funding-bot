### Non-goal

- 不碰 real-money execution、dry-run flag、kill-switch、Bitfinex `offer/new` 接線 (defer to 4.2)
- 不碰 strategy code
- 不碰 `modules/backtest/` → `modules/strategies/` module boundary 重構 (defer Phase 5 housekeeping spec; rationale: refactor 跟 stability 無關，Kent Beck / Fowler 派建議 refactor 跟 feature dev 永遠分開)

### D2 — settings.py URL transform

**Driver coexistence decision**:

| 派別 | 做法 | 採用率 |
|---|---|---|
| **Sync alembic env.py + async runtime engine** (**選**) | alembic 用 psycopg、runtime 用 asyncpg、兩個 accessor | SQLAlchemy 2.0 官方 docs / FastAPI Tiangolo template 共識 |
| Async alembic (run_async wrapper) | 一個 driver | "less common" per SQLAlchemy docs；env.py 複雜 |

**API shape**:

```python
class Settings:
    DATABASE_URL: str  # env，Neon dashboard 原 libpq-style

    @property
    def database_url_async(self) -> str:
        """asyncpg via SQLAlchemy: daemon runtime"""
        # 4 transforms:
        #   scheme: postgresql:// → postgresql+asyncpg://
        #   sslmode=require → ssl=require
        #   drop &channel_binding=require (asyncpg 不支援)
        #   drop -pooler 後綴 (asyncpg prepared stmt 跟 PgBouncer transaction-mode 衝突)

    @property
    def database_url_sync(self) -> str:
        """psycopg via SQLAlchemy: alembic"""
        # 2 transforms:
        #   scheme: postgresql:// → postgresql+psycopg://
        #   drop -pooler 後綴
        # (保留 sslmode + channel_binding，psycopg 支援)
```

**Implementation**: `urllib.parse.urlsplit` + `parse_qsl` 改寫 + `urlunsplit`。不用 regex (URL 結構嚴格、urlparse 標準庫穩定)。

**Image dep**: 加 `psycopg[binary]` 進 `[project] dependencies` (對應 roadmap R2 alembic psycopg2 import error)。

### D3 — DB pool keepalive

**兩層機制**:

| Layer | 機制 | 目的 |
|---|---|---|
| SQLAlchemy engine | `create_async_engine(..., pool_pre_ping=True, pool_recycle=600)` | 取 connection 前 self-check；過 10 min 自動 recycle |
| Daemon-level keepalive task | 每 **5 min** 跑 `await conn.execute(text("SELECT 1"))` | 確保即使 idle 也 < 10min recycle 邊界 |

**Interval rationale**: AWS RDS Proxy / HikariCP / Heroku Postgres 共識 — application keepalive = pool_recycle / 2 (2× safety margin)。Neon serverless 15min idle 切，10 min recycle 在 cut 前、5 min keepalive 在 recycle 前。

### D4 — TaskGroup + tenacity + heartbeat registry

**Supervision pattern decision**:

| 派別 | 出處 | 採用 |
|---|---|---|
| Pre-3.11 `asyncio.gather` + try/except | Discord.py 早期 / CCXT examples / Hummingbot | **anti-pattern** — Phase 4.1 zombie 對應 |
| **Layered: TaskGroup + sub-task tenacity retry + Koyeb restart** (**選**) | PEP 654 + 12-factor disposability + Erlang one_for_all + D. Beazley "Modern Python Concurrency" 2024 | Modern Python async daemon mainstream |
| Custom OTP-style per-task supervisor | aiomisc / Erlang OTP one_for_one | solo dev maintain cost 高，且 5 sub-task coupling 強不需要 per-task policy |
| Pure let-it-crash | Erlang 純血派 | WS reconnect rate limit + orderbook state 丟代價高 |
| Process-level isolation + watchdog | HFT (Citadel / HRT) | 需 multi-process budget，Koyeb PaaS 不適合 |

**結構**:

```python
class Daemon:
    heartbeat: dict[str, datetime]  # {name: last_active_ts}
    _shutdown: bool = False

    async def run(self):
        async with asyncio.TaskGroup() as tg:
            tg.create_task(self._ws_ingest(),     name="ws")
            tg.create_task(self._candle_writer(), name="candle_writer")
            tg.create_task(self._scheduler(),     name="scheduler")
            tg.create_task(self._axiom_emit(),    name="axiom")
            tg.create_task(self._health_check(),  name="health_check")
        # any sub-task raise → TaskGroup cancel all → exit non-zero → Koyeb restart
```

**Sub-task internal pattern** (every sub-task):

```python
async def _candle_writer(self):
    @retry(
        retry=retry_if_exception_type(TransientError),
        wait=wait_exponential(multiplier=1, min=1, max=30),
        stop=stop_after_attempt(5),  # 5 attempts → re-raise (fatal escalation)
        before_sleep=before_sleep_log(logger, logging.WARNING),
    )
    async def _write_one():
        async with self.db.acquire() as conn:
            await self._do_write(conn)
            self.heartbeat["candle_writer"] = datetime.now(UTC)

    while not self._shutdown:
        try:
            await _write_one()
        except FatalError:
            raise  # propagate to TaskGroup
```

**Transient vs Fatal classification** (per WebSocket RFC 6455 + Bitfinex WS API spec + ccxt-pro convention):

| Error 來源 | Transient → tenacity retry | Fatal → raise → TaskGroup |
|---|---|---|
| DB | `asyncpg.InterfaceError` / `ConnectionDoesNotExistError` (idle / closed) | `InvalidPasswordError` / `InvalidCatalogNameError` (auth / db gone) |
| WS — RFC 1000-1999 | 1000 / 1001 / 1006 / 1011 (reconnect with backoff) | — |
| WS — RFC 1008 (rate limit) | transient **with long backoff** | — |
| WS — Bitfinex 4xxx | 4408+ (預設保守 retry) | 4400 / 4401 / 4404 (auth / channel error) |
| Axiom HTTP | 5xx / 408 / 429 / network timeout | 401 / 403 (token bad) |
| Scheduler | tick missed (log + continue, next boundary 仍有效) | system clock 倒退 (極端，no retry) |
| Network primitives | `socket.gaierror` (DNS) / TLS handshake fail | — |
| `asyncio.TimeoutError` | context-dependent, default transient with cap | — |
| Memory | — | `MemoryError` (let-it-crash) |
| OS | — | `OSError` port taken |

**Heartbeat registry threshold** (per Prometheus + APM convention):

| Sub-task | Progress unit | Stale threshold | Rationale |
|---|---|---|---|
| `ws` | 收 1 個 Bitfinex message | 30s | Bitfinex public channel `hb` 每 15-30s 一次 |
| `candle_writer` | 寫 1 個 candle row | 90s | 1 min K bar + 安全 buffer |
| `scheduler` | tick 1 次 boundary | 65 min | hourly boundary (C1/C2 hourly 主 cell) |
| `axiom` | flush 1 個 event | 60s | trading event 頻率 + 5min health heartbeat |
| `health_check` | emit 1 次 (含 self heartbeat) | 6 min | 5min heartbeat + buffer |

**Health monitoring pattern decision**:

| 派別 | 出處 | 為何不選 |
|---|---|---|
| k8s liveness probe / process self-report | k8s convention | process alive ≠ progress alive — Phase 4.1 zombie root cause |
| **Registry pattern + per-task staleness threshold** (**選**) | Prometheus gauge with `last_update_time` + AWS X-Ray / Datadog APM | 業界共識，跟 sub-task 內部 progress 同步 |
| Pub-sub heartbeat event | Discord.py / aio frameworks | overkill for 5 sub-task |
| asyncio Task inspection | Python stdlib | task awaiting socket = "running" yet no progress → 不可靠 |

Integration test 模擬 SIGTERM lifecycle:

2. 主 thread send SIGTERM (`os.kill(os.getpid(), signal.SIGTERM)`)
3. 驗證:

4. **Timeout test**: 模擬 axiom flush 卡 70s (> 55s grace) → 驗 daemon force-exit 而非無限等

### D6 — Paper smoke outcome-based exit

| Trigger | Exit code | 意義 |
|---|---|---|
| Emit ≥ N signal events (N = count of active cells in cells.yaml × 1 hourly round; current N = 11) | 0 OK | 達標 |
| Timeout (90 min) 內 emit 0 個 | 1 ERROR | bug |
| Timeout 內 emit 1-10 個 | 2 PARTIAL | 跨整點但部分 cell 沒觸發 |

Smoke runner 從 axiom query 計數 (`event_type=signal AND phase=paper`)，不從 daemon 內部 counter (per Honeycomb / DataDog / OpenTelemetry end-to-end observability best practice — 驗 emit chain 端到端 work)。

Timeout 90 min 保證至少跨 1 個 hourly boundary (最壞 daemon 在 hh:59 起動，hh+1:30 達 1 round)。

## Data Flow

### Flow 1 — Heartbeat registry update

```
sub-task internal loop                  daemon coordinator state         health_check sub-task
─────────────────────────              ────────────────────────         ───────────────────────
candle_writer: while:                   heartbeat: dict[name, dt]        every 30s tick:
  await db.write(row) ────────────►     "candle_writer": now()             for name, ts in registry:
  registry[name] = now()                                                     age = now() - ts
                                                                             if age > threshold[name]:
                                                                               emit health_check
                                                                                 level=warn|error
                                                                                 status=degraded|down
                                                                                 check_target=<name>
                                                                                 error_message=...
                                                                             if age > 3×threshold:
                                                                               raise FatalError
                                                                                 # → TaskGroup cancel
```

Sub-task 在 loop 內每完成一個 progress unit 後寫 registry。health_check 不寫 axiom 整個 registry，只 emit 異常者 (避免 cardinality 爆)。3× threshold 是「嚴重 stale」進 fatal escalation 上限 (per Prometheus 3-bucket alert convention)。

### Flow 2 — Transient retry (in-sub-task)

```
sub-task tick                tenacity                          tracking
─────────────────            ─────────────                     ──────────
try:
  await db.write() ─► InterfaceError (connection closed)
                              │
                              ▼
                       wait_exponential
                       (1s, 2s, 4s, 8s...)
                              │
                              ▼ retry attempt 2
                       await db.write() ─► OK ─► registry[name] = now()
                              │
                       (success: stop retrying,
                        continue main loop)
```

Tenacity decorator 包裝最內層 IO op，不是整個 while loop。Retry 期間 registry **不更新** (沒 progress) → health_check 會察覺。超過 `stop_after_attempt(5)` → raise → TaskGroup 處理 (fatal escalation)。

### Flow 3 — Fatal escalation

```
sub-task                    TaskGroup                 daemon main           Koyeb runtime
─────────                   ─────────                 ────────────          ──────────────
raise FatalError ─────────► __aexit__:
                            cancel other 4 tasks
                            wait for them to finish
                            re-raise ExceptionGroup ─► caught in main
                                                       cleanup:
                                                         axiom.flush()
                                                         db.dispose()
                                                       sys.exit(1)         ─► detect exit
                                                                              restart container
                                                                              (~30s downtime)
```

TaskGroup `__aexit__` 自動 cancel 所有 sibling tasks (`CancelledError`)。每 sub-task 收到 `CancelledError` 在 `finally` 做 local cleanup。Main loop catch `ExceptionGroup` → 統一 cleanup (axiom flush + db dispose) → exit non-zero。

Koyeb auto-restart policy 預期 1-3 次 restart 後 stabilize；連 5 次 restart 內 → CrashLoopBackOff (Koyeb 對應 service status `degraded`)。Daemon **不自帶** retry counter — 交給 platform 處理 (k8s default 5 restart in 5 min → backoff)。

### Flow 4 — Graceful shutdown (SIGTERM)

```
Koyeb deploy / scale event       Python signal handler              TaskGroup
──────────────────────────       ──────────────────────             ─────────
SIGTERM ─────────────────────►   daemon._shutdown = True
                                 cancel main task ─────────────────► __aexit__:
                                                                     cancel sub-tasks
                                                                     each sub-task sees:
                                                                       CancelledError
                                                                       → finally:
                                                                         self.cleanup_local()
                                                                       → return
                                                                     wait_for(all, timeout=55s)
                                                                     ──► all done
                                                                     OR ──► timeout: log + force exit
                                                                  ◄── return to main
                                 axiom.flush(timeout=3s)
                                 db.dispose()
                                 sys.exit(0)
```

55s timeout = Koyeb 60s grace − 5s buffer (axiom flush + DB dispose)。若 axiom flush 卡 → 不無限等，3s 後強制 drop pending events (emit warning)。

### Flow 5 — Paper smoke outcome-based exit

```
smoke runner                      daemon (paper mode)              axiom API
─────────────                     ─────────────────                ──────────
start daemon subprocess ─────────► running emit:signal events ────► ingest
sleep 60s (warmup)
loop:
  query axiom:
    dataset=bfx
    filter: event_type=signal,
            phase=paper,
            timestamp > start_time
    count(*) ────────────────────────────────────────────────────► response
  count >= N → SIGTERM daemon, exit 0  # N = len(cells.yaml active cells); current 11
  elapsed > 90 min:
    if count >= 1: SIGTERM, exit 2 PARTIAL
    else: SIGTERM, exit 1 ERROR
  else: sleep 30s, loop
```

Runner sleep 60s warmup 給 daemon connect WS、首批 candle 進來。Query interval 30s (axiom rate limit 寬鬆)。SIGTERM 給 daemon 走 Flow 4 graceful shutdown。

Trade-off: a sub-task whose `finally` cleanup hangs will only force-exit when Koyeb kills the container; testing this requires platform-level verification not unit/integration tests.

### Rollback Plan

**Trigger conditions** (任一觸發 rollback):
- Gate 1 chaos 任一 step 失敗 + 2 次 debug 內沒解
- Gate 2 期間 daemon entered CrashLoopBackOff (> 5 restart in 5 min)
- ≥ 2hr 連續沒 emit signal event

**Rollback 動作**:
1. **Code rollback**: Koyeb dashboard → service `fee91ed2` → Deployments → previous deployment "Redeploy" (Koyeb 一鍵 rollback；不需 git revert)
2. **DB rollback**: D2 driver swap 不涉 schema migration、rollback 等於 driver dep 變回去；alembic schema unchanged。**無 down migration 需求**
3. **Diagnose**: rollback 後 commit working state，spec 補 "Lessons" 段，重新 plan 攻略再來

**No-rollback 情境**:
- Gate 1 chaos 部分 fail 但已知原因 (e.g., axiom 自身 outage) → retry chaos
- 短暫 degraded (< 5 min) → heartbeat 設計就是處理這個，acceptable

## Risks

| Risk | 機率 | 影響 | Mitigation |
|---|---|---|---|
| TaskGroup `__aexit__` 在 Python 3.13 行為跟 docs 不一致 | 低 | sub-task cleanup 行為 surprising | I-D4 integration test cover；docs reference D. Beazley 2024 + PEP 654 已驗 stable |
| Tenacity `wait_exponential(max=30)` 在 high frequency error 場景仍打太多 retry | 中 | API rate limit | `stop_after_attempt(5)` 保證 5 attempt cap；fatal escalation 帶走 |
| Heartbeat registry race condition (concurrent write from 5 sub-task) | 中 | last_active_ts 落差 | Dict update atomicity in GIL 下安全；如改 free-threaded 3.13t 需加 lock |
| Koyeb 60s grace 實際 < 60s | 低 | shutdown 超時 force exit | 已留 5s buffer (55s wait_for cap)；timeout fall-through 寫 log 不爆 |
| Smoke runner 90 min cap 不夠跨 hourly boundary (極端 timezone case) | 低 | exit code 1 false ERROR | timeout 90 min 已 cover 最壞 hh:59 起；若仍 ERROR runbook 改 120 min retry |
| psycopg dep image size 增加 | 低 | ~5MB image bloat | Acceptable trade-off for alembic sync simplicity |
| Neon connection pooler 後綴 (-pooler) 在某 region 不 consistent | 低 | URL transform 漏失 | T-D2 fixture cover；urlparse 處理 hostname pattern |
