# Phase 4.3 — LOCF + staleness budget for sparse p30 cells

## Context

Phase 4.2.1 G1 smoke 24h audit 暴露：8 p2/a30 cells emit signal 完整 (8/8 + 9/9 cycles)，但 **3 p30 cells 0/3 emit**（fUSD_p30 MR 2/9、fUSD_p30 RP 4/9、fUST_p30 RP 7/9）。Root cause hypothesis：Bitfinex p30（30-day rolling avg funding rate）channel 1h 內 ~1/3 機率有 close，剩下整 hour skip。Buffer 拉再長都沒用（candle 根本不來，不是 scheduler race）。

但 Phase 3b WFO p30 cells 全 qualified（RP 6/6 margin 0.072-0.121；MR fUSD_p30 margin 0.099）— 直接移除等於放棄已驗證策略。Prior state：Phase 4.2.1 G1 spec C2 列為 backlog（commit `55f6036`），4.2 main brainstorm defer 等 4.3 calibration 結果。

## Options Considered

7 個 industry pattern（funding/lending bot domain，慢變數 → 1-2h stale 是否 break strategy）：

- **A. LOCF (Last Observation Carried Forward)** — Bloomberg fixing / pandas ffill / quant 論文 missing-rate 預設做法（chosen）
- **B. Stale-while-revalidate + TTL** — CDN cache / Redis EX 模式
- **C. Multi-source fallback** — 多 venue 拼湊資料
- **D. Watermark + grace period** — Flink / Kafka stream pattern
- **E. Synthetic / Kalman filter** — 缺值用 model 推斷
- **F. Skip-period (current)** — pre-4.3 行為，sparse cell 直接 SKIP signal
- **G. Pre-warmup backfill** — startup 一次性補齊 history

並行 sub-axis（每個都 2+ 真選項）：

- **Spec packaging**：Runtime-only / Mega-spec (LOCF + decision policy + G2 + 4.4 一次到位) / 3-axis (runtime + backtest re-run + G2 audit) (chosen)
- **Primitive 範圍**：Single shared function across daemon/replay/backtest (chosen, Citadel-style) ↔ Per-layer 各寫一遍
- **Staleness semantic**：Both-tier (soft stale w/ metadata + hard DEGRADED) (chosen) ↔ Binary (fresh vs absent)
- **Budget config**：Global only ↔ Per-cell override in cells.yaml (chosen, p30 = 12h vs default 2h)
- **Ship gate**：Single-criterion (backtest only / G2 only) ↔ AND-gate matrix (backtest × G2) (chosen)

## Decision

- **D1 = LOCF** (A) 為 sparse handling 主軸
- **D2 = 3-axis spec packaging** — runtime LOCF + Phase 3b sparse-ified WFO re-run + G2 live calibration audit 並行驗
- **D3 = `reindex_and_ffill` 為 shared primitive in `candles/service.py`**；daemon live / replay engine / Phase 3b backtest 三層都 call 同一函式
- **D4 = Both-tier semantic**：soft tier 內（stale ≤ budget）→ emit signal 帶 `is_stale/stale_seconds/budget_seconds`；hard tier 外（stale > budget）→ skip signal + emit `signal_pipeline DEGRADED`
- **D5 = cells.yaml per-cell `staleness_budget_hours` override**；global default `2h`（p2/a30 dense），p30 sparse cells override `12h`
- **D6 = SIGNAL_PIPELINE 從 scan_staleness fatal escalation carve-out**；reason=`stale_exceeded` 永不升 fatal（sparse 是預期 channel physics，不是 system failure）
- **D7 = AND-gate ship matrix**：Backtest verdict × G2 verdict → 雙 GREEN 才 SHIP for 4.4 canary，任一 RED 即 BLOCK
- **D8 = Sensitivity sweep grid 6h/12h/24h × 2 cells × 2 strategies = 12 WFO runs**；驗 budget choice robustness

## Rationale

- **D1 — LOCF 而非其他 6 個**：
  - p30 = 30d rolling avg funding rate → 1h 變化 < 1%，**慢變數 1-2h stale 不 break strategy 假設**是 quant LOCF 適用前提
  - 同類 funding/lending bots（Bitfinex/Aave/Compound）公開實作大多用 LOCF + 6-24h staleness threshold
  - 不選 B (stale-while-revalidate)：適用但 max staleness budget 概念跟 LOCF 等價，LOCF 更貼 quant 慣用語
  - 不選 C (multi-source)：Bitfinex 是該 channel 唯一 venue，no fallback source
  - 不選 D (watermark)：治標 race 不治 sparse — 我們已知 channel physics 是 sparse 不是 race
  - 不選 E (synthetic/Kalman)：overkill，p30 變化太慢，模型 overfit 風險
  - 不選 F (skip-period)：浪費 6/6 qualified cells，回到問題原點
  - 不選 G (pre-warmup only)：initial OK 但 ongoing tick 仍需 ffill — 一定要 LOCF
  - **代價**：regime shift 後 last value 不代表 current → mitigation 是 staleness budget cap + G2 calibration audit
- **D2 — 3-axis spec packaging**：
  - Runtime-only：違反專案既有「避免 daemon/replay engine 行為差導致 backtest/live divergence」原則
  - Mega-spec：decision policy 應 evidence-based wait G2 audit 結果，提前包進 spec 等於猜
  - 3-axis：4.3 backlog recommend 三層；ship gate 兩 axis AND 對應 Phase 4 conservative discipline
- **D3 — Shared primitive Citadel-style**：
  - 三層各寫一遍 = 三條 path drift surface area（Phase 4.3 收尾的 warmup.py bug 就是這 class — 加 LOCF 到 2 path 但漏第三 path，5/20 prod first-tick CP1 divergence；後續 commit `bbcc684` + `0001fd3` 再 refactor 抽 `build_strategy_at_boundary` 進一步收斂）
  - **代價**：函式參數設計要考慮三層共用，初期 API spec 投資較高
- **D4 — Both-tier 而非 binary**：
  - Soft tier 帶 metadata 讓 G2 audit 比較 stale vs fresh win-rate degradation，evidence-based 決定要不要 ship；binary 喪失 mid-tier 訊號
  - Hard tier 仍 DEGRADED 保健康事件流，monitor 看得到
  - **代價**：observability schema 多 3 fields (`is_stale/stale_seconds/budget_seconds`)，pre-4.3 events 缺欄位 → APL query 容錯 query 時要考慮
- **D5 — Per-cell override 而非 global**：
  - p30 sparse 一致 12h 安全（30d rolling 12h 內變化 < 1%），p2 dense 維持 2h 抓 fast anomaly
  - Global 12h 會放寬 p2 sensitivity → 假 positive signal 變多
  - **代價**：cells.yaml 多一欄；mitigation `staleness_budget_hours: None = use global default` 為 None-default 保 backward compat
- **D6 — SIGNAL_PIPELINE carve-out**：
  - sparse 是 channel physics（Bitfinex 沒 push 是 venue 行為，daemon 沒 hung）；scan_staleness fatal escalation 是給「真 task hung」用
  - Reason 分類：`stale_exceeded` (sparse, never fatal) vs `task_hung` / `connection_lost` (legit fatal)
  - **代價**：HealthMonitor scan loop 多一段 read-only emit path（per-cell pipeline status → axiom）；mitigation 抽 `_emit_locf_degraded` helper
- **D7 — AND-gate ship matrix**：
  - 純 backtest GREEN 但 G2 fresh-vs-stale degradation 過大 → 假設 violated；單 G2 GREEN 但 backtest 沒驗 LOCF semantic on Phase 3b data → blind ship
  - 雙 axis AND 是 conservative discipline；symptom 是 4.4 canary 之前必過兩 gate
  - **代價**：要跑兩個 verification cycle（backtest 立即 + G2 等 2-3 週 shadow）
- **D8 — 12-run grid (6h/12h/24h × 2 cells × 2 strategies)**：
  - 6h 太緊（quick degradation surface） / 12h target / 24h 寬鬆 sanity → 3-point grid 看 budget 對 win-rate 敏感度
  - 2 cells (fUSD_p30 / fUST_p30) × 2 strategies (RP / MR) = 12 runs 是 minimum viable matrix
  - **代價**：12 WFO runs 一次 ~5-10 min DB load（per-cell pass 約 1 min on Koyeb instance）

## Lessons

### Rules

- **R1 — 多 path 共用 semantic 必須抽 single source of truth**。spec 寫 Citadel-style shared primitive，但 implementer 仍可能漏第三 path（warmup.py）。`Rule: 任何「N 條 code path 都要做 X」的 design，要在 plan 明確列 N 條 path 清單 + final cross-task reviewer 必驗 N 條都 call 同一函式（不是 inline copy logic）`

### Observations

- **O1 — Industry spectrum surface 7 個 pattern + domain-fit reasoning** 是 ADR-quality decision；單純「我覺得 LOCF 比較好」會被半年後 review 質疑。即使 9/10 reader 會直接挑 LOCF，列 6 個不選的 + 為何 trade-off 不划算，比省略要 review-safe
