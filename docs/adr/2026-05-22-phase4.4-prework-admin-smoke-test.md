# Phase 4.4 prework — Admin Smoke-Test Endpoint

## Context

Phase 4.3 ship `dfece968` HEALTHY 只證 process 活 + 4 個 prod log code path proof，沒 deploy-time gate 驗 middleware chain 端到端 emit 對的 event types 到 Axiom。Phase 4.3 ADR Followup R 段明示「Phase 4.4 prework 必做：POST /admin/smoke-test endpoint」就是補這個 gap。Phase 4.4 接下來會接 live executor，wiring drift 風險升，pre-prod 補 deploy gate 最便宜時機。

## Options Considered

### Approach — Deploy verification 模式
- A1. Health endpoint only — 不證 business logic
- A2. Boot-time self-check — deploy gate fail-fast
- A3. Admin endpoint (on-demand) — ad-hoc verify
- A4. Synthetic monitoring (24/7) — solo single-tenant overkill
- **A5. 複合 (A2 + A3)** — Stripe production readiness / Netflix canary + smoke

### Sub — Synthetic event 隔離
- **a. 獨立 account_id**（選）— Stripe `acct_test_*` / Datadog Synthetic
- b. Payload flag `is_test=true` — 每 consumer 都要 check
- c. 獨立 dataset/topic — 2x cost
- d. In-memory mock — 不驗 ingest pipeline

### Sub — Bus subscribe / unsubscribe API
- a. Subscribe-only — ephemeral 會洩漏
- b. Disposal token (RxJS) — Python async 不 idiomatic
- c. Explicit unsubscribe — try/finally boilerplate
- **d. async context manager**（選）— OpenTelemetry SDK / Trio nurseries

### Sub — Smoke verification 載體
- a. Ephemeral domain object (mini ledger) — 借 replay 概念負債
- **b. Spy / Recorder pattern**（選）— Greg Young ES fixtures / Axon Fixture
- c. Snapshot restore — race-prone
- d. Mock-all-the-way — 跟 unit 重複

## Decision

- **D1 = 原 spec §2.2 + §3.4**：boot smoke L2 + admin endpoint L3 複合，共用 SmokeRunner core
- **D2 = 原 spec §2.3 + §3.3**：`account_id="smoke_test"` 隔離 + ledger 3 handler 加 account_id guard (Phase 5+ multi-tenant 預留)
- **D3 = 原 spec §2.4 + §3.7**：bus 新增 `subscription()` async context manager；既有 `subscribe()` 留給 permanent wirings
- **D4 = 原 spec §2.5 + §3.6**：smoke 驗證用 `EventRecorder` spy pattern (30 行 dataclass)，不借 ledger
- **D5 = 原 spec §1 + §3.4**：4 assertion levels (L1-L4)；boot L2 / endpoint L3 default + `?level=L2` query param

## Rationale

- **D1**：boot smoke = deploy gate fail-fast；admin endpoint = ad-hoc verify (env var 改後不需 redeploy)。Pre-prod 兩者一起做 cost ≈ 單做一個。不選 synthetic monitoring (24/7)：cron + alert 配套 vs solo single-tenant ROI 不對等
- **D2**：`ledger.replay_from_axiom` 既有 `account_id` filter (line 135) 零改動受惠；Axiom 端 `account_id="smoke_test"` query 即拿 smoke history。代價：bus live update path 補 3 handler guard (+1 行/handler) — Phase 5+ 必要的東西免費附送
- **D3**：smoke 是「scoped subscription」典型場景，`async with bus.subscription(...):` 跑完自動 cleanup、exception path 不漏；symmetric with `async with session:` / `async with lock:`。Bus API 多一個方法、`subscribe()` 不變
- **D4**：smoke 驗的是「chain 把對的 event 對的 payload 對的順序丟到 bus」，不是「exposure 算對」(後者 ledger unit test 涵蓋)。不借 ledger 避免 replay 機制 + replay_floor_hit_count 概念混淆心智模型
- **D5**：boot 30s timeout 等不起 Axiom ingest 5-10s 不穩定 (cold start + ingest pipeline 抖動)；endpoint 才負擔得起端到端驗證 latency。Boot smoke fail 設計成不 crash daemon → L3 fail noise 反而讓 boot 沒治療效果。代價：boot 抓不到 Axiom ingest pipeline broken (endpoint 補)

## Lessons

### Rules

- **R1**: Production smoke endpoint 第一次跑就抓自己 bug = 設計 ROI 對的訊號。`Rule:` deploy-time gate 第一次跑就 surface local mock 沒測到的 wire-level mismatch → 設計合理；連續 5-10 次部署都 pass 沒抓過 → over-engineering 候選需 prune。前 5-10 次命中率是評估基準
- **R2**: External service integration 的 contract test 要驗 wire-level 行為，不只 client-side mock。`Rule:` integration 寫 fake client 時，fake 的行為要 mirror real service 端的 schema / 序列化結果，不是 echo input；對 Axiom / Bitfinex 等 nested object 服務尤其關鍵（Axiom payload flatten 踩坑為證）
- **R3**: Subagent-driven workflow 連續跑同 pattern 後可主動 tier 升級。`Rule:` 連續 2-3 phase 跑同 workflow 後 (4.3 15 task → 4.4 12 task)，mechanical pattern 已被消化 → 全 sonnet 不需 haiku 分流、combined review prompt 從更早 task 起用；不等 explicit pain signal 才簡化

### Observations

- **O1**: User 主動觸發「什麼是 best practice / 業界怎麼做」連續 4 次 (Phase 4.3 是 3 次) → decision protocol working signal 越來越 stable。Architecture-level 議題主動先攤 industry spectrum、不等 user 第二次問是預設行為
- **O2**: Spec self-review 抓到 1 個 implementation blocker (Q1：`_AxiomQueryAdapter` 是 4.3 stub 回 `[]`，L3 round-trip 不可行) → 寫 spec 結尾的 Open Questions 段確實有 catch latent issues 的價值
