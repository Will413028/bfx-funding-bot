# Phase 4.2 Chaos Test Specs (executed in 4.4 first week, NOT 4.2 ship gate)

Parent spec: `docs/superpowers/specs/2026-05-21-phase4.2-design.md` section Testing → Chaos.

Aligned with Phase 4.2.1 Gate 1 chaos pattern (Neon Suspend Step 2).
Each chaos is run against canary 4.4 deployment in first week, results logged
to `wiki/projects/bfx-funding-bot/`.

## C1 — Bitfinex rate limit storm
**Inject**: Toxiproxy 429 responses for 1 min on all funding endpoints.
**Expected**: tenacity exhausted → emit `order_submit status=failed
reason=transient_exhausted` → next signal cycle generates fresh decision.
Daemon never crashes (no FatalError raised). After storm ends, normal flow
resumes within one signal cycle.
**Pass gate**: 0 daemon restarts; ≥1 `order_submit status=failed` event during
storm window; ≥1 successful `order_submit status=submitted` within 5 min
of storm ending.

## C2 — Network partition mid-submit (cid reuse verification)
**Inject**: Toxiproxy drop 50% packets for 30s on offer/submit endpoint.
**Expected**: tenacity retries with same cid (CC2 immutable-across-retries).
Bitfinex auto-dedupes if attempt 1 actually reached venue.
**Pass gate**: Axiom query for the affected window shows no 2× same cid
producing real fills (`order_fill is_simulated=false COUNT BY cid` MAX=1).

## C3 — FillTracker partial outage
**Inject**: Mock `/offers` 200 OK + `/credits` always 500 (run against shadow
not canary — paper executor wired with mock httpx, so isolated).
**Expected**: Atomic abort (CC3) — last_state remains, no order events
emitted from incomplete data. After 3 consecutive failed ticks, emit
`health_check check_target=fill_tracker status=degraded`.
**Pass gate**: 0 spurious `order_status_change` events; ≥1 degraded
`health_check` emitted; no daemon restart.

## C4 — Safety chain guard hang
**Inject**: Hot-patch one CalibratedGuard's `evaluate` to `await
asyncio.sleep(60)` (in canary build before deploy; not production).
**Expected**: `asyncio.wait_for(timeout=GUARD_EVAL_TIMEOUT_SECONDS=2s)` →
TimeoutError → fail-closed → `safety_trigger level=critical
reason=eval_timeout`. Daemon never deadlocks. Other guards never reach
since chain short-circuits after timeout failure.
**Pass gate**: For the inject window, 0 `order_submit` events; ≥1
`safety_trigger reason=eval_timeout`; signal cycle latency stays bounded
(no cell stalled >5s).
